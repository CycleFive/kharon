# Compose E2E: path B over WebSocket with no VPN — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A compose E2E that proves a path-B fill over `wss://…/connector`, using the base compose with no `compose.vpn.yml`, and shows that kharond still binds loopback only.

**Architecture:**
- The variant layers a new overlay, `deploy/compose/e2e/compose.e2e-ws.yml`, on the **base** `deploy/compose/docker-compose.yml`. Nothing else is layered in.
- A fake edge stands in for Cloudflare plus cloudflared. It is socat terminating TLS in the holder's netns, relaying to kharond's public ingress at `127.0.0.1:8790`.
- The agent host runs headless Chromium (the existing test image). A `connector` container shares its netns and runs `kharon-agent-connector` with `transport = "ws"`, dialing the fake edge.
- The test plays the agent:
  - **MCP side:** `POST /mcp` through the same fake edge.
  - **Browser side:** opening its own tabs, over a harness-only network that kharond's netns has no route to.

**Tech stack:** Docker Compose overlays, socat (OpenSSL), rcgen certs, tokio/rustls test code, GitHub Actions (`image.yml`).

**Spec:** issue #220 item 2 and its acceptance criterion ("A compose E2E proves a path-B fill over `/connector` with no `compose.vpn.yml`"). The plan is on #220, comment 6762002736. Behaviour under test is in SPEC REQ-ARCH-002 (connector over WebSocket, OQ-14) and REQ-DEP-006 (B), and the design is `docs/superpowers/specs/2026-11-09-connector-websocket-design.md`.

## Review Focus

1. **Stale state from an earlier local run.** Leftover `kharon-e2e-ws` containers, volumes or a `run-ws/` directory must not break the run or skew its results. Setup starts with `down -v --remove-orphans` and recreates `run-ws/`.
2. **Connector backoff.** If the connector starts before kharond is ready, it backs off with full jitter up to 30 s. The wait for the attach line must allow for at least one full cap (wait 90 s, polling).
3. **Docker inter-network isolation is an assumption.** The no-route check (Task 3) has a positive control: the host reaches `10.68.0.2:9222`. Its failure message has to say which side failed.
4. **The fake edge's listener is in the holder's netns.** The listener check must keep kharond's own set exact, with only loopback listeners. The only extra listener it allows is socat on `10.67.0.1:8443`, plus Docker's `127.0.0.11:*`.
5. **The existing E2E must behave the same after the Task 1 extraction.** CI runs both jobs, and `git diff --color-moved` must show Task 1 as moves plus parameterisation.

### Task 2: The ws stack, and the connector's `--check` through the fake edge

  Services:

  - `fake-edge`: image `kharon-e2e-agent-host:local`, `network_mode: "service:holder"`. Its entrypoint is socat: `OPENSSL-LISTEN:8443,bind=10.67.0.1,fork,reuseaddr,verify=0,cert=…,key=…` to `TCP:127.0.0.1:8790`. The edge cert and key are mounted read-only from `run-ws/edge/`.
  - `vaultwarden`: extends the fixture service, as in `compose.e2e.yml`.
  - `kharon`: `image: kharon:e2e`. It mounts `run-ws/kharon.toml`, the fixture vault CA, and the inner `[connector]` cert and key.
  - `agent-host`: builds `./e2e/agent-host` (unchanged) as `kharon-e2e-agent-host:local`.

    - `AGENT_HOST_ADDR: 10.68.0.2`, so the existing CDP relay serves the harness network only.
    - `PAGE_HOST_RULES: "MAP canary.example.test 10.67.0.254"`.
    - Mount `./e2e/run-ws/page:/e2e:ro`.
  - `connector`: builds `deploy/compose/e2e/connector/Dockerfile` as `kharon-e2e-connector:local`, with `network_mode: "service:agent-host"`, `restart: "no"`. It mounts `run-ws/connector/` (holding `connector.toml`, `token` and `edge-ca.pem`) at `/etc/kharon-connector:ro`. Command: `--config /etc/kharon-connector/connector.toml`.
  - Secrets and volumes are named the way `compose.e2e.yml` names them.
  - Networks `edge` and `harness` are defined with the subnets from Global Constraints.

**`run()` setup, in order:**
1. Run `down -v --remove-orphans` for the project, and recreate `run-ws/`.
2. Read the fixture env and add the canary item.
3. Generate the TLS material with rcgen:
   - the page cert and SPKI (`compose_support::page_tls`);
   - an **edge CA** and a leaf for `kharon.e2e.test`, signed by it;
   - the **inner** `[connector]` cert and key. `broker_pin` is the SHA-256 of its DER.
4. Run `up -d --no-build agent-host`, which creates the networks. Then `browser_ws_url("10.68.0.2:9222")`, and start the page server on `10.67.0.254`.
5. Create the agent token with `kharond::api::token::generate("alpha")` and the tunnel token with `generate_tunnel("alpha")`. Write `run-ws/kharon.toml`:
   - `mode = "sync"`, plus the same `[bitwarden]` as the wg E2E;
   - `[agents.alpha] token_hash`, `connector_token_hash`, `cdp = { endpoint = "ws://127.0.0.1:9222", via = "agent_connector" }`;
   - a `[policy]` with fill budgets covering the fills plus the approval retry;
   - `[audit] checkpoint_local_only = true`;
   - `[public_ingress] listen = "127.0.0.1:8790"`;
   - `[owner_ui] listen = "127.0.0.1:8788"` with its origin;
   - `[connector] websocket = true`, `tls_cert_file`, `tls_key_file`, and no `listen`;
   - **no `[api]`**.
6. Write `run-ws/connector/connector.toml`:
   - `transport = "ws"`, `broker_url = "wss://kharon.e2e.test:8443/connector"`;
   - `broker_pin`, `agent_id = "alpha"`, `token_file`, `cdp = "127.0.0.1:9222"`;
   - `outer_ca_file` set to the edge CA.

   The token file is mode 0600 and readable by the connector container's uid.
7. Run `up -d --no-build kharon fake-edge`. Wait for kharond's `public ingress listening on 127.0.0.1:8790` line, matching what `main.rs` prints when websocket is on.
8. Unlock with `docker_on_tty(["exec","-it",<kharond>,"kharon","unlock"], …)`, as the wg E2E does.
9. Run the **`--check`** before the long-running connector starts, so there's no live session to evict: `compose run --rm --no-deps connector --config /etc/kharon-connector/connector.toml --check`. Record its exit code and stdout.
10. Run `up -d --no-build connector`. Wait, for up to 90 s, until kharond's log shows `agent connector attached: agent=alpha transport=ws`.

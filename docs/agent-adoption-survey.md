# kharon adoption survey: agent platforms

> Point-in-time research record from Claude Duet, Nov 14, 2026. Check claims against current code and the linked sources before relying on them.

> **Owner decisions (Nov 14, 2026):** 1Password is out (no integration planned; kharon stays on CDP + Bitwarden). [roadmap.md](roadmap.md) (#332) sets the order: v0.5.0 OpenClaw (#334–#336), v0.6.0 Hermes (#337–#339), then one minor per CDP host. This ranking is input to that roadmap, not the plan.

Nov 14, 2026.

The three open agents with the best fit are Hermes Agent, OpenClaw and browser-use (the roadmap takes OpenClaw first, then Hermes): all three drive a Chromium over a CDP URL you choose, take kharon in days, and together reach over 750k GitHub stars. Two closed agents already work: kharon's CDP fill is proven with Nyx on Grok Bot, and with Muse in the VM 125 live test on 2026-11-14. dots signed with 1Password on 2026-10-22 and documents no CDP, so kharon reaches only its MCP side so far.

1. **Hermes Agent** is the best technical fit: its browser defaults to 127.0.0.1:9222, its MCP client speaks OAuth 2.1, and `browser_exec` can open a tab in kharon's own browser context, so it works with kharon as it is. Its built-in vault fills from `bw` with no per-fill approval, which is the pitch.
2. **OpenClaw** is the biggest audience (393k stars) with the clearest gap: its 1Password plugin hands secret values to the model. An MCP entry plus a ClawHub skill is the whole integration.
3. **browser-use** is the default library under many agents (2.1M PyPI downloads a week). Its own docs call `sensitive_data` "not a sandbox"; a small `kharon-browser-use` package fixes exactly that.

One kharon change would open most of the rest: an owner-approved way to fill a tab outside kharon's own browser context, which Playwright MCP and Chrome DevTools MCP (and through them Codex CLI, Gemini CLI, Cursor and Claude Code) need. Bitwarden's Agent Access SDK is an ally, not a rival: it delivers plaintext to the agent and does no fill.

Grok Bot and Muse are the proof that a closed vendor agent can work: kharon's CDP fill runs with Nyx on Grok Bot and ran with Muse in the VM 125 live test. Both score at or near the top, but the next step for them is a written setup guide rather than integration work, which is why the push list above names the three open agents. dots has not been tried.

## Ranking

Scores are my judgment from the notes below (inference): fit 1 to 5 is how much of kharon works there without vendor help; reach 1 to 5 is audience size. Sorted by fit times reach; ties go to the higher fit, then the open agent. Muse's fit was raised from 1 to 4 after the VM 125 live test proved its fill (inference: 4, not 5, because Muse's app has no official custom-MCP setting).

| # | Platform | Reach (as read) | Browser control | kharon hook | kharon path and size | Fit × reach |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Hermes Agent | ~260k stars | CDP, `browser.cdp_url` defaults to 127.0.0.1:9222; `browser_exec` sends raw CDP | MCP client with headers, OAuth 2.1 | MCP config + `cdp_url` + skill; works with kharon as it is. Days | 5 × 4 = 20 |
| 2 | OpenClaw | 393k stars; 3.2M users (Apr 2026) | CDP, managed profile on 18800 or `cdpUrl` + `attachOnly` | MCP client with headers, OAuth; ClawHub skills | MCP config + connector `cdp` on 18800 + ClawHub skill. Days | 4 × 5 = 20 |
| 3 | Muse | 10M+ users (Oct 2026) | Vendor Secure VM; Sentinel gates egress | Vetted Connector Platform; ad-hoc MCP unofficial | Working: CDP fill proven in the VM 125 live test. Next: a setup guide, then the Connector Platform for official reach | 4 × 5 = 20 |
| 4 | browser-use | 120k stars; 2.1M PyPI/week | CDP, `cdp_url` | Custom `@tools.action` (no MCP client since 1.0) | `kharon-browser-use` package, 150 to 300 lines + docs PR. Days | 4 × 4 = 16 |

| 10 | Skyvern | 23.1k stars | Playwright, attaches over CDP | Custom Credential Service API | Implement API (returns plaintext) or upstream delegated fill | 2 × 2 = 4 |
| 11 | dots / ChatGPT Work | No numbers found | Vendor cloud Chrome | OAuth 2.1 + CIMD plugins, which kharon already speaks | MCP side only so far; fill path unproven | 1 × 4 = 4 |

The shared kharon-side blocker (inference from `kharon_context` in [mcp-tools.json](api/mcp-tools.json)): kharon fills only tabs created in its own browser context, and other tabs are `target_not_owned`. Hermes can create that tab itself with raw CDP; OpenClaw and browser-use need a skill or action that does; Playwright MCP and DevTools MCP drive the default context and can't. An owner-approved way to adopt an existing tab would unlock row 6 and simplify rows 2 and 4. The roadmap's design issues take this up for OpenClaw in [#334](https://github.com/CycleFive/kharon/issues/334) and for Hermes in [#337](https://github.com/CycleFive/kharon/issues/337). The connector's `cdp` setting is already configurable, so OpenClaw's port 18800 needs no change.

## Platform notes

All pages read 2026-11-14 unless a date is given. Star counts are from the repo pages that day.

### Open agents and frameworks

- **[OpenClaw](https://github.com/openclaw/openclaw)** (MIT, OpenClaw Foundation since 2026-07-08). 393k stars; 3.2M active users and 44k+ ClawHub skills per a [2026-04-07 article](https://www.trendingtopics.eu/openclaw-numbers/), which also counts about 155k exposed instances. Browser: a managed profile on CDP port 18800, or any profile with `cdpUrl` + `attachOnly: true` ([docs](https://docs.openclaw.ai/tools/browser/remote.md)). MCP client: stdio, streamable HTTP, headers, OAuth ([docs](https://docs.openclaw.ai/tools/mcp.md)). Secrets: its [1Password plugin](https://docs.openclaw.ai/plugins/onepassword) returns values to the model "without secret masking"; no fill broker. Path: `mcp.servers.kharon` + a ClawHub skill + a shared-CDP profile. Size: days.
- **[Hermes Agent](https://github.com/NousResearch/hermes-agent)** (MIT, Nous Research). About 260k stars, launched 2026-02-25, ships `hermes claw migrate` ([article, 2026-07-27](https://startupfortune.com/hermes-agent-crosses-214000-github-stars-as-developers-abandon-commercial-ai-agent-frameworks/)). Browser: CDP-native, `browser.cdp_url` defaults to 127.0.0.1:9222 ([docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/browser)). MCP client with headers and OAuth 2.1 ([docs](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)). Secrets: a built-in [browser_vault](https://hermes-agent.nousresearch.com/docs/user-guide/features/credential-vault) fills over CDP from `bw` or `op` with no per-fill approval for logins. Its LoginBackend plugin seam returns the password to Hermes, so it is a poor fit. A marketplace plugin, [hermes-vault-broker](https://hermes-agent.nousresearch.com/marketplace/hermes-vault-broker) (v0.1.0, about 2026-11-11), already does broker-types-over-CDP: prior art and a competitor. Path: MCP config + `cdp_url` + a skill; later an upstream "delegated fill" backend. Size: days, then weeks.
- **[browser-use](https://github.com/browser-use/browser-use)** (MIT, Browser Use). 120.0k stars; 2.11M PyPI downloads a week ([pypistats](https://pypistats.org/packages/browser-use)); 1.0.3 on 2026-11-12. Browser: CDP, `Browser(cdp_url=...)`. Extension: custom `@tools.action`; 1.0 dropped the built-in MCP client ([docs](https://docs.browser-use.com/customize/mcp-client)). Secrets: `sensitive_data` placeholders, which its docs say are "not a sandbox" ([docs](https://docs.browser-use.com/open-source/secrets.md)). Browser Use is a 1Password launch partner. Path: a `kharon-browser-use` package with a login action calling kharon's MCP. Size: 150 to 300 lines plus a docs page.
- **[Playwright MCP](https://github.com/microsoft/playwright-mcp)** (Microsoft). 38.9k stars; 10.5M npm downloads in the week to 2026-11-10 ([npm](https://api.npmjs.org/downloads/point/last-week/@playwright/mcp)). Its README has setup for about 20 hosts, Cursor, Cline, Goose, Claude Code, Codex, Gemini CLI and Grok among them. `--cdp-endpoint` attaches to an existing Chromium; extension mode exposes no port, so it is a poor fit. `--secrets` only redacts tool output. Path: a shared-CDP launcher (or `kharon-connector --launch-chromium`) + per-host config snippets. Size: 1 to 3 days.
- **[Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp)** (Google). 54.7k stars; 2.4M npm downloads a week. `--browserUrl` / `--wsEndpoint`; `--autoConnect` reaches a user's Chrome 144+. Path: same recipe as Playwright MCP. Size: docs only.
- **[OpenHands](https://github.com/OpenHands/OpenHands)** (MIT core, All Hands AI). 92.6k stars. MCP: streamable HTTP with bearer, headers or OAuth ([docs](https://docs.openhands.dev/openhands/usage/settings/mcp-settings.md)). Browser tool is built on browser-use with no `cdp_url` option. Secrets become env vars the agent's code can read. Path: sandbox image with the connector + an upstream PR exposing `cdp_url`. Size: 1 to 2 weeks.
- **[Stagehand](https://github.com/browserbase/stagehand) / Browserbase.** 25.5k stars; Browserbase raised $40M in June 2025. Stagehand v4 attaches with `cdpUrl`; Browserbase sessions expose a wss `connectUrl`. Browserbase's [1Password Agentic Autofill](https://docs.browserbase.com/integrations/1password/agentic-autofill) (2026-10-22) is the closest analog to kharon: backend-driven, CDP, human approval, status only. Path: let the connector dial a wss CDP URL with an auth header + a ~100-line Stagehand example. Size: days.
- **[Skyvern](https://github.com/Skyvern-AI/skyvern)** (AGPL-3.0). 23.1k stars. Attaches with `BROWSER_REMOTE_DEBUGGING_URL`. Already supports Bitwarden, 1Password and a [Custom Credential Service](https://skyvern.com/docs/credentials/custom-credential-service), but that API's `GET` returns plaintext to Skyvern. Path: implement it (200 to 400 lines of Rust, weakens the guarantee) or upstream a delegated-fill vault type. Size: days or weeks.
- **[Agent Zero](https://github.com/agent0ai/agent-zero)** (MIT). 19.6k stars. Host Chromium over remote debugging via `A0_HOST_BROWSER_REMOTE_DEBUGGING_ENDPOINTS`; MCP with bearer headers, OAuth undocumented. Path: config + skill. Small reach.
- **Goose** (55.9k stars, now under the Linux Foundation's Agentic AI Foundation) and **Cline** (70.9k stars): MCP hosts with streamable HTTP, headers and OAuth. They reach kharon through the Playwright MCP recipe. Size: a config snippet each.

### Closed and commercial agents

Every closed agent the owner named runs a vendor-owned cloud browser and already has a native 1Password path. None documents a CDP endpoint or an open program for other credential providers. Grok Bot and Muse work anyway: kharon's CDP fill is proven with Nyx on Grok Bot and was proven with Muse in the VM 125 live test. dots stays MCP-only until the fill is tried on its VM.

- **[Grok Bot](https://docs.x.ai/grok-bot/overview)** (SpaceXSI). Beta 2026-08-11; in every SuperGrok and Cursor Pro/Teams plan from [2026-08-26](https://x.ai/news/grok-bot-more-plans). Persistent cloud computer with browser, filesystem and terminal; "works with any MCP or API"; Grok app [connectors](https://docs.x.ai/grok/connectors) take any public MCP URL. Sign-in order: its own Vault, then a connected password manager (only 1Password named; Bitwarden is only a CSV import source), then a secure form ([vault docs](https://docs.x.ai/grok-bot/vault)). Live 1Password partner at launch. 418k weekly users as of 2026-09-14 (Bloomberg via [PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2026/spacexai-grok-bot-gains-early-traction-ai-agent-push/)). [Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps) docs allow remote MCP with headers or OAuth, command MCP servers on the cloud computer, and a sudo option for Enterprise. Status: working and proven, kharon's CDP fill runs with Nyx on Grok Bot (owner, 2026-11-14). Next: a written setup guide for other Grok Bot users.
- **[Muse](https://about.fb.com/news/2026/09/introducing-muse)** (Meta). Launched 2026-09-08 in the US. Runs on "Muse Secure VM" with its own browser; a Sentinel agent approves anything the VM sends out. [1Password](https://support.1password.com/1password-muse/) live via Settings > Connectors. No custom-MCP setting in the app; Muse Code takes streamable HTTP and OAuth per a [third-party write-up](https://parallel.ai/articles/meta-muse-custom-integrations) (2026-11-05). Sentinel could block the connector's wss tunnel (inference); the VM 125 live test on 2026-11-14 got a fill through, and this survey did not compare that setup with a stock Muse install. Over 10M US and Canada users per Zuckerberg on the Q3 call ([report, 2026-10-21](https://stocktwits.com/news-articles/markets/equity/meta-s-muse-hits-over-10-m-users-since-launch-zuckerberg-says-company-gearing-up-to-serve-1-b-people/cZxvrfNRBw2)). The official [Connector Platform](https://platform.muse.ai/docs) takes API or MCP connectors after business verification and a three-stage review. Status: working and proven, kharon's CDP fill ran with Muse in the VM 125 live test (2026-11-14). Next: a written setup guide for other Muse users.
- **[dots](https://learn.chatgpt.com/docs/dots/computers-and-apps)** and **ChatGPT Work** (OpenAI). dots launched at DevDay [2026-09-29](https://siliconangle.com/2026/09/29/openai-launches-dots-always-on-ai-agents-in-chatgpt-with-their-own-cloud-computers/) for Pro and Business Premium: each dot has a cloud computer with a browser and terminal, signs in by private form or take-over, and can be allowed onto the owner's own computer. No CDP or MCP in the docs I could open. 1Password support for dots is announced, not live. Its MCP plugins use OAuth 2.1 with [Client ID Metadata Documents](https://developers.openai.com/plugins/build/auth) preferred, which kharon's Connect already speaks, and [MCP Events](https://developers.openai.com/plugins/build/mcp-events) can push signed webhooks into a dot. No user numbers found. ChatGPT Atlas was shut down on [2026-08-09](https://help-lb.openai.com/en/articles/20001371-evolving-atlas-into-chatgpt-for-browser-based-agentic-work).
- **[Codex CLI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)** (OpenAI, open source). About 135k stars ([star-history](https://www.star-history.com/openai/codex), 2026-11-13). Remote MCP with bearer env var or OAuth; docs suggest Chrome DevTools MCP or Playwright for the browser. Direct fit through the Playwright/DevTools recipe.
- **[Gemini CLI](https://geminicli.com/docs/tools/mcp-server/)** (Google, open source). About 109k stars (2026-11-13). Remote MCP with headers and OAuth; no browser of its own, uses chrome-devtools-mcp. Direct fit through the recipe. Gemini in Chrome auto browse and Gemini Spark use Google Password Manager only; closed. Project Mariner shut down about 2026-05-06.
- **[Manus](https://manus.im/blog/manus-browser-operator)**. Meta's purchase (announced 2025-12-29) was blocked by China's NDRC on 2026-04-27 per a [secondary source](https://codersera.com/blog/manus-ai-2026-status-meta-block-desktop-app/). Browser Operator extension drives local Chrome; [custom MCP](https://manus.im/docs/zh-tw/integrations/custom-mcp) takes a URL with a bearer token. Possible fit via local Chrome with CDP open; uncertain company status.
- **[Perplexity Comet](https://1password.com/blog/1password-now-available-in-comet-the-ai-browser-by-perplexity)**. 1Password built in since 2025-09-17; unclear whether users can add MCP servers. Low priority.

## Bitwarden Agent Access SDK and 1Password

Agent Access is mostly an ally: it moves a credential to the agent with per-request approval, but it does no browser fill and the agent's process ends up holding the plaintext. kharon supplies exactly the missing no-exposure fill layer (inference).

| Offering | What it does | Secret reaches agent process? | Browser fill | Status (as read 2026-11-14) |
| --- | --- | --- | --- | --- |
| [Bitwarden Agent Access SDK](https://github.com/bitwarden/agent-access) | Noise NNpsk2 channel over a WebSocket relay; RemoteClient (agent) asks UserClient (vault) by domain or id; user approves at the CLI | Yes: `aac connect` prints JSON, `aac run` puts it in a child's env | No | Early alpha, announced 2026-03-24 ([blog](https://bitwarden.com/blog/introducing-agent-access-sdk/)); Apache-2.0, 148 stars; Rust with Python and WASM bindings |
| [Bitwarden MCP server](https://github.com/bitwarden/mcp-server) | Local stdio wrapper over `bw`; ~30 admin tools added Oct 2025 | Yes, into model context (README warns of it) | No | GPL-3.0, 254 stars |
| [OneCLI + Agent Access](https://www.onecli.sh/blog/bitwarden-agent-access-sdk-onecli) | HTTP gateway injecting API keys into outbound requests | No (header injection) | No, API keys only | Alpha, 2026-03-30 |
| [1Password for Agents](https://1password.com/press/2026/october/1password-for-agents-trust-layer-personal-ai-agents) | Extension in the agent's browser fills from an attested enclave after app approval | No | Yes | Launched 2026-10-22, partner program |

Bitwarden's roadmap (2026-03-24 post) lists an approval browser extension "coming soon" and a native Browserbase integration in development. Neither had shipped by Browserbase's 2026-10-22 [changelog](https://browserbase.com/changelog/1password-for-agents), which names only 1Password. A 2026-06-10 [follow-up](https://bitwarden.com/blog/shadow-ai-agents-how-to-secure-credential-access-with-agent-access-sdk/) names Claude, Copilot, Cursor and OpenClaw as compatible, with no new roadmap.

1Password's launch partners on 2026-10-22: Muse (Meta), Claude Duet (Anthropic), ChatGPT Work and dots (OpenAI), Grok Bot (SpaceXSI), Town, Browserbase, Browser Use, Dana, Instinct, KERNEL, Perplexity, Ramp, Tomo and Wajo. Every closed agent the owner named is already signed to 1Password; OpenClaw and Hermes are not on the list.

What this means for kharon (inference):

- **Ally path:** kharon becomes an Agent Access RemoteClient as a second vault backend, keeps its CDP fill, and pitches itself to Bitwarden as the reference browser integration, the way OneCLI is for API keys.
- **Competitor risk:** if Bitwarden's Browserbase integration or extension gains fill, it covers kharon's core job for Bitwarden users on Browserbase. Watch that repo and changelog.
- **kharon's ground:** Bitwarden and Vaultwarden users, self-hosting, open source, per-agent tokens, one-shot grants. That is where 1Password's partner list leaves room.

## Dropped, caveats and method

- **Dropped:** LaVague (last PyPI release 2024-08-05, about 254 downloads a month, [pypistats](https://pypistats.org/packages/lavague)); ChatGPT Atlas (shut down 2026-08-09); Project Mariner (shut down about 2026-05-06); Operator (folded into ChatGPT agent, from memory, not checked). Gemini in Chrome and Gemini Spark use Google Password Manager only. Perplexity Comet has 1Password built in and unclear custom MCP. Lindy, Town and Claude Duet were not researched in depth.
- **Competing prior art:** Hermes's built-in `browser_vault`, the [hermes-vault-broker](https://hermes-agent.nousresearch.com/marketplace/hermes-vault-broker) plugin (about 2026-11-11), the OpenClaw "Browser Secure" skill (claims Bitwarden and 1Password backends, no mechanism shown), and Skyvern's Bitwarden provider.
- **Not verified:** whether two CDP clients typing into one tab race (Chrome supports several clients since [Chrome 63](https://developer.chrome.com/blog/new-in-devtools-63)); whether a dot's VM lets the connector reach its browser's CDP; Muse custom MCP beyond third-party write-ups; star counts read from repo pages on 2026-11-14, not the API. Chrome 136+ ignores `--remote-debugging-port` on the default profile, so every recipe needs a dedicated `--user-data-dir` ([Chrome blog, 2025-03-17](https://developer.chrome.com/blog/remote-debugging-port)).
- **Method:** read-only. kharon's README, agent-runtime-setup, mcp-tools.json and 1password-agent-model docs on master; vendor docs, repo pages, press releases and news, each linked where cited. Nothing was posted, filed or signed in to. The Grok Bot and Muse fill results come from live tests run outside this survey. Scores are inference.

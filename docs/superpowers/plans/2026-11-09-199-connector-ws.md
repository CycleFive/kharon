# #199 agent connector over WebSocket — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kharon-agent-connector` dials `wss://<public host>/connector` through the Cloudflare Tunnel. Inside the WebSocket it runs today's pinned TLS (1.3 only), the auth record and the mux, unchanged, so path B fills work with no VPN.

**Architecture:**
- **WebSocket adapter.** A WebSocket byte-stream adapter in `kharon-connector` makes binary messages look like `AsyncRead + AsyncWrite`.
- **Generic pinned TLS.** The pinned-TLS client and server become generic over the stream and take the TLS version set.
- **Agent dial.** The agent dials TCP (or an HTTP CONNECT proxy), then outer TLS with WebPKI and the system roots, then the upgrade with subprotocol `kharon-connector.v1`, then the existing inner stack.
- **Broker side.** kharond's `[public_ingress]` mounts `GET /connector`. It checks the upgrade, holds one of 8 pre-auth slots until `AUTH_OK`, peeks for a TLS ClientHello, then hands the stream to the same `Hub` as `:8789`.
- **Shutdown.** WebSocket sessions are tracked, so shutdown ends them.
- **Audit.** `connector_auth_fail` and `connector_replaced` are rate-limited audit events.

**Tech Stack:** Rust: tokio, rustls 0.23 (aws-lc-rs), tokio-rustls 0.26, tokio-tungstenite 0.24 (already in the tree), axum 0.8 / hyper 1 upgrade, rustls-native-certs 0.8 (already in the tree), rand 0.8.

**Spec:** `docs/superpowers/specs/2026-11-09-connector-websocket-design.md` (#214, approved by Nyx and Muse), plus their build notes on #214 (listed under Review Focus). Issue #199's ACs.

**Deferred, a ruling:** the design proposed showing the agent's connector session start time in the owner UI. That moves to #208 (N2), which reworks the owner UI behind the edge. #199 ships the `connector_replaced` audit entry, which is the record of evictions.

## Global Constraints

- **The inner protocol** is connector wire v1, byte for byte. `WIRE_VERSION` stays `1`, and the auth record, frames and constants are unchanged.
- **Subprotocol:** `kharon-connector.v1`, the exact string. The server answers with exactly that value or refuses.
- **TLS versions.**
  - The WebSocket path's inner TLS is **TLS 1.3 only**, on both client and server, with no early data.
  - The raw `:8789` path keeps `rustls::DEFAULT_VERSIONS` on both sides, unchanged.
  - Both facts are asserted by tests.
- **The upgrade.** It needs all of these:
  - `GET /connector`;
  - `Upgrade: websocket`, case-insensitive;
  - `Connection` containing `upgrade`;
  - `Sec-WebSocket-Version: 13`;
  - a `Sec-WebSocket-Key`;
  - `Sec-WebSocket-Protocol` listing `kharon-connector.v1`.

  A missing or wrong item gets **400**. Any `Origin` header gets **403**. A full pre-auth budget gets **503**. `Sec-WebSocket-Extensions` is ignored: no compression is ever negotiated.
- **WebSocket limits.**
  - `max_message_size = max_frame_size = 64 * 1024`, and unmasked client frames are refused (the tungstenite default).
  - A text message closes the socket.
  - A write sends at most `MAX_WS_WRITE = 16 * 1024 + 256` bytes per message.
- **Pre-auth budget.**
  - `WS_PREAUTH_SLOTS = 8` slots, separate from the raw listener's existing `Semaphore(4)`.
  - The permit is acquired **before** the 101 and held until `AUTH_OK` or failure. If the acquire happens after the upgrade and loses a race, the socket closes.
  - Argon2id runs inside the slot, on the blocking pool.
- **WebSocket deadlines.** The inner TLS handshake gets **5 s** (raw stays 10 s) and the hello 5 s.
  - The first inner record must look like a TLS ClientHello: byte 0 `0x16`, bytes 1–2 `0x03 0x01`–`0x03 0x04`, byte 5 `0x01`. Anything else closes the socket before rustls sees it, and is counted.
- **Agent backoff.**
  - Transport legs back off exponentially with **full jitter**, from 1 s to a 30 s cap.
  - `Unauthorized` and `ProxyAuth` wait a fixed 60 s, as today.
  - A session that authenticated (`Ok(())` or `Disconnected`) and lived ≥ 10 s resets the delay.
- **Escalation.** After **2 min** with no authenticated session, log one summary line, then repeat it every **10 min**:

  ```
  kharon-agent-connector: no broker session for <dur> (<n> attempts); last failure: <leg line>
  ```

  It resets on `AUTH_OK`.
- **Log lines.** They have fixed text and never contain a token, credential, proxy body or peer body. Upgrade failures print the HTTP status as received: `websocket upgrade answered <code>`. That's Nyx's build note 3; the code may be Cloudflare's 52x.
- **Audit.**
  - `connector_auth_fail` is written only when the claimed agent id is configured. It carries `agent_id`, `transport` (`tls`|`ws`), `detail_code` (`unauthorized`|`protocol`) and `suppressed` (u64), at most one entry per agent per 60 s.
    **Amended (implementation):** `protocol` is not emitted, because a malformed hello carries no attributable agent id; `detail_code` is `unauthorized`.
  - `connector_replaced` is written when a session evicts a live one. It carries `agent_id`, the new session's `transport`, `old_session_secs` and `suppressed`, under the same bound.
  - Both appends are best effort: a failed append is logged and never blocks auth.
  - Unknown agent ids and junk are only counted in the logs: one line per minute, and only when the count is non-zero.
- **Rust.** Typed serde only, with no `serde_json::json!`/`Value` in new non-test code. Tests may use them for CDP stubs, as the existing path-B tests do.
- **Gates.** `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, and `cargo deny check` (run it if it's installed locally; CI runs it).
- **Commits** end with exactly these two lines, and no other `Co-Authored-By` line:

  ```
  Claude-Session: https://claude.ai/code/session_017zqkE9gtxZrLyEWBDCjXMG
  Co-Authored-By: Claude & Lothrop (cycle.five@proton.me)
  ```

- **No version bump** (the workspace is still `0.0.0`).

## Review Focus (the reviewers' build notes; each one is a test in the owning task)

1. *(Muse 1)* **A held-open WebSocket session must end at shutdown.** Aborting the axum serve task leaves accepted connections running. Task 4 tracks the sessions and tests it.
2. *(Muse 2)* **The TLS version set is a parameter.** Under it, the WebSocket path is 1.3 only and the raw path is unchanged. Task 1 tests both directions.
3. *(Muse 3, Nyx 2)* **At most 8 sockets are pre-auth at once, including the Argon2id phase.** Task 4 asserts it through `Hub::ws_preauth_in_flight()`, not only the 503.
4. *(Nyx 5)* **The canary relay checks the outer plaintext.** The plaintext after the outer TLS, before WebSocket decoding, holds neither the canary nor the credential. Task 6 tests it.
5. *(Nyx 1, 3, 4)* These are covered:
   - the early non-ClientHello close (Task 4);
   - statuses printed as received (Task 2);
   - `connector_replaced` carrying the old session's age (Task 5).

- Consumes: Task 1's items.

  - `pub enum Transport { Tls { broker: SocketAddr }, Ws { host: String, port: u16, path: String, outer_tls: bool } }`.
    - `outer_tls` is `true` in every production config, and the binary always sets it so.
    - `false` is for in-process tests that dial kharond's plain-loopback `[public_ingress]` directly. Its doc comment says so.

    | Variant | Display |
    |---|---|
    | `Dns` | `cannot resolve the broker host`. The binary prints the host from its own config next to this line |
    | `Tcp { kind: std::io::ErrorKind }` | `tcp connect failed (<kind>)` |

    | `ProxyAuth` | unchanged |
    | `OuterTls` | `outer TLS to the broker host failed` |
    | `Upgrade { status: u16 }` | `websocket upgrade answered <status>` (0 means no HTTP response; Display then says `websocket upgrade got no HTTP response`) |
    | `InnerTls` | `inner TLS handshake failed` |
    | `BadCert`, `Unauthorized`, `Protocol`, `Disconnected`, `CdpNotLoopback` | unchanged |

    The variants stay `Copy + PartialEq + Eq`.
  - `pub async fn connect_and_auth(params: &AgentParams) -> Result<AuthedSession, ClientError>`. `AuthedSession` wraps the authenticated inner stream, boxed as `Box<dyn AsyncRead + AsyncWrite + Send + Unpin>`. `run_agent_once` becomes `connect_and_auth`, then `serve_agent`.
  - `pub async fn check_once(params: &AgentParams) -> Vec<(Leg, Result<(), ClientError>)>` walks the legs up to `AUTH_OK`, then closes without opening CDP. `Leg` is an enum: `Dns`, `Tcp`, `Proxy`, `OuterTls`, `Upgrade`, `InnerTls`, `Auth`.
- **The `Ws` path:**
  1. Resolve `host:port`.
  2. TCP, or a CONNECT to `host:port` through the proxy.
  3. Outer TLS, with SNI `host`, ALPN `http/1.1`, WebPKI against `outer_roots` or the system roots, and `DEFAULT_VERSIONS`.
  4. `client_async_with_config` with `Sec-WebSocket-Protocol: kharon-connector.v1`, no `Origin` header, and `ws_config()`. The response must echo the subprotocol, or the error is `Upgrade { status: 101 }`.
  5. `WsByteStream`, then `connect_pinned_stream(server_name, pin, ws, Tls13Only)`, then auth.
- **The `Tls` path** is today's code with the new error variants.

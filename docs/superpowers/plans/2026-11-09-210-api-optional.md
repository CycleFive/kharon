# #210: kharond runs with no `[api]` listener — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let kharond start with no `[api]` section when `[public_ingress]` is configured, so the compose base case has no listener a dashboard mis-route could expose. Keep refusing a config with neither.

**Architecture:** `daemon::check`/`start` accept a missing `[api]` when `[public_ingress]` is set. `Daemon`'s agent-API listener becomes optional, and `run()` serves it only when it is bound, otherwise waiting on `shutdown`. The main.rs banner and `--check` say whether the agent API is on. The compose example drops `[api]` from its base; the VPN overlay docs add it back on the WireGuard address.

**Tech Stack:** Rust (tokio, axum), integration tests in `crates/kharond/tests`, Docker Compose docs.

**Spec:** issue #210 and its claim comment (https://github.com/CycleFive/kharon/issues/210#issuecomment-6752313414). Background: `docs/superpowers/specs/2026-11-09-portable-gateway-design.md` › *The shape* (the `[api]` row says "off" in the base case).

## Global Constraints

- **Startup refusal.** With neither `[api]` nor `[public_ingress]`, startup and `--check` both exit **78** (`EX_CONFIG`), with code `no_agent_listener`.
  - The message: ``no agent listener configured; set `[api] listen` (a VPN address) or `[public_ingress] listen` (the edge's loopback)``.
  - It replaces `ApiListenMissing` / `api_listen_missing`; no alias is kept.
- **Banner.** With `[api]` configured, the start banner stays byte-for-byte `kharond: agent API listening on <addr> (locked)`. Existing tests and the compose E2E wait on that line.
- **Banner without `[api]`.** The banner prints `kharond: agent API off (no [api]; agents reach POST /mcp on [public_ingress])` in its place. The owner-socket, owner-UI and public-ingress lines are unchanged.
- **`--check`.** It prints `kharond: config ok (<n> agent(s), agent API on <addr>)` as today, or `kharond: config ok (<n> agent(s), agent API off)`.
- **Shutdown.** The order in `Daemon::run` is unchanged:
  - the public ingress drains for at most `PUBLIC_INGRESS_DRAIN` after the shutdown future fires;
  - then the checkpoint timer, request expiry, owner tasks and live sync stop;
  - then `checkpoint_audit_now()`.
- **Rust:** typed serde only; no `serde_json::json!`/`Value` in new non-test code. Existing tests may keep their `json!` use.
- **Gates:** `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- **Commits** end with exactly these two lines, and no other `Co-Authored-By` line:

- **No version bump:** the workspace is still `0.0.0`.

## Review Focus

1. **A daemon with no `[api]` returns from `run()` before shutdown is asked,** because nothing else awaits the shutdown future. Task 1's binary test keeps the process alive for a `POST /mcp` round trip, then sends SIGTERM and expects exit 0.
2. **A path-B config (`via = "agent_connector"`) with `[connector]` but no `[api]`** must still start: agents use `/mcp` on the public ingress, and the connector carries CDP. Task 1 adds a `--check` case for it.
3. **`owner_ui`-only configs** (an `[owner_ui]` and no agent listener) must still be refused. Agents need a way in, and the owner UI isn't one. That's the `no_agent_listener` test, with `[owner_ui]` present.
4. **A stray `[api]` assumption in tests** that call `daemon.local_addr()` must keep compiling. `Option::unwrap` keeps `local_addr().unwrap()` valid, and the workspace build in Task 1's gates proves it. `daemon::check` now returns `Option`, so its callers (`req_aud_002_offhost.rs` ~145, ~197) need the same care: compare against `Some(addr)`.
